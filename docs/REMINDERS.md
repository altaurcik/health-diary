# Напоминания об измерениях

Реализовано и проверено 2026-09-26.

## Интерфейс

В профиле — список будильников, сортируемый по времени. Каждое расписание
можно добавить, открыть для редактирования, включить/выключить и удалить.
Последнее удаление отменяется кнопкой «Вернуть» в открытом разделе.
Типы: «Всё» (давление и вес), «Вес», «Давление» (с необязательным пульсом).
Число расписаний не ограничено двумя временами или двумя показателями.

Повтор задаётся напрямую кнопками Пн–Вс, без выбора периодичности из списка.
Все семь дней — каждый день; можно выделить произвольные дни. Есть «Все дни»
и «Снять все». Активное расписание без дней отклоняется. Месячный повтор убран
по явному пожеланию владельца. Время и дни следуют часовому поясу профиля;
показанные на главной даты/время — поясу устройства.

В существующем дневнике изменения списка сохраняются сразу; не требуют
«Сохранить настройки» для остальных полей профиля. Во время первоначальной
настройки расписания — часть черновика и сохраняются при создании дневника.
Новый дневник начинает с пустого списка. Демо содержит два вымышленных будильника.

Если расписаний нет, под быстрым вводом на главной видна короткая кнопка
«Настроить напоминания об измерениях». Она открывает профиль с прокруткой
и фокусом на нужном разделе. Если все выключены — ссылка на их включение.

## Хранение и выполнение

Сохраняется прежний ключ localStorage `healthnote.diary.v1`; версия содержимого
теперь 2. `schedules` — массив `{id, kind, enabled, time, frequency, days}`.
Новые записи используют weekly с явным массивом дней. Загрузчик поддерживает
старые daily и переводит их на все семь дней. Старые месячные будильники
становятся выключенными с пустым выбором дней: интерфейс просит выбрать дни,
ежедневные уведомления вместо месячных автоматически не включаются.

v1 с объектом `schedules.bp/weight` и массивами `times` преобразуется в отдельные
будильники для каждого времени. Их id детерминированы; пропуски, выполнение и
отложенные напоминания переносятся. Миграция только в памяти, до следующего
успешного сохранения исходный localStorage не перезаписывается. Записи измерений
не удаляются. Ошибка формата сохраняет прежнюю защиту от перезаписи данных.

Задание напоминания имеет ключ с id расписания, местной датой, временем и типом
измерения. «Всё» имеет отдельные задания для давления и веса: запись одного
не завершает второе. Пропуск/перенос на 30 минут касается оставшихся заданий
видимого напоминания. Одинаковое время разных будильников не смешивает их.
Отключённые/удалённые расписания не генерируют заданий. Перенос через полночь
учтён. Как и раньше, пропущенный час при переходе на летнее время пропускается.

Это настройки и карточки внутри открытого сайта. Web Push, звук при закрытой
вкладке, системный будильник и Telegram-доставка не реализованы. Это указано
в профиле и на главной; разрешения браузера на уведомления не запрашиваются.

## Проверки

26 тестов Node: время и дни, независимые одинаковые времена, частичное выполнение
«Всё», пустые/отключённые расписания, перенос через полночь, DST, миграция v1,
сохранение/чтение v2, снятие месячного повтора, ошибки ввода и прежняя логика дневника.
Production build и проверка diff прошли.

Браузер на демоданных: создание с временем 09:30, тип «Вес», редактирование
произвольных дней (Пн/Ср/Пт), отклонение пустого выбора дней, сохранение,
выключение, удаление и отмена. Удаление всех расписаний показывает ссылку
на главной; клик фокусирует заголовок раздела. Проверены 390 и 1280 px,
без горизонтального переполнения. Реальные iOS/Android и фоновая доставка
не проверялись.
