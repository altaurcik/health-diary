# Инструкции для проекта «Дневник здоровья»

Перед работой прочитай `PROJECT_MAP.md` в этом каталоге.
После изменений обновляй карту: назначение, структуру, точки входа,
зависимости, конфигурацию, команды запуска и проверки, решения и открытые
вопросы. Указывай дату проверки и отделяй реализованное от планов.

Работай над проектом в этом каталоге. В `../PROJECT_MAP.md` поддерживай
ссылку на локальную карту; подробности проекта там не дублируй.
Не сохраняй в картах секреты и личные медицинские записи.

Основной интерфейс — Telegram Mini App на телефоне в вертикальной ориентации.
Порядок разработки: сначала самостоятельная веб-версия, работающая
в обычном браузере, затем интеграция той же версии в Telegram Mini App.
На первом этапе запуск и основные экраны не должны требовать Telegram SDK,
Telegram ID или токен бота. Telegram-интеграцию держать отдельно
от компонентов интерфейса и логики дневника.
Проектируй сначала для мобильного экрана; учитывай тему Telegram, safe area
и экранную клавиатуру. Адаптируй содержимое к доступной ширине и высоте.
По просьбе владельца установлены только в этом проекте:

- UI UX Pro Max: `.agents/skills/ui-ux-pro-max/SKILL.md` — читать при выборе
  визуальных правил и проектировании UI.
- Impeccable: `.agents/skills/impeccable/SKILL.md` — читать при анализе,
  проверке и доработке дизайна.
- Telegram UI + React 18: зависимости `frontend/package.json`.

Даже при работе из общего чата VPN читай нужные skills по этим путям,
разрешённым относительно health-diary, и запускай их команды из корня
health-diary. Не устанавливай эти skills глобально или в соседние проекты.
Контекст продукта уже описан в `docs/PRODUCT_BRIEF.md` и `PROJECT_MAP.md`;
не задавай повторно вопросы, на которые там есть ответы. Требования владельца
и проекта имеют приоритет над общими советами внешних skills.
Версии, локальные адаптации, команды и проверки — в `docs/UI_TOOLS_SETUP.md`.
Другие инструменты из `docs/UI_TOOLS_RESEARCH.md` остаются кандидатами.

Git использовать для кода и технической документации. Личные записи,
вложения и выгрузки хранить только вне репозитория или в исключённых
каталогах `private/`, `data/`, `uploads/`, `backups/`; секреты — в `.env`
или `secrets/`. Перед коммитом проверяй содержимое diff и список файлов.
Не добавляй исключённые файлы принудительно.

Перед работой с сервером прочитай `../SERVER_MAP.md` и соблюдай
инструкции из `../AGENTS.md`. Серверные подробности веди в серверной карте.
