# Время записей

Проверено: 2026-09-26. Требование владельца: время устройства для ввода,
графиков, календарных периодов и сортировок; единый timestamp параллельно.

## Хранение

Новые измерения содержат:

| Поле | Значение |
| --- | --- |
| `at` | Момент измерения в ISO 8601 UTC с `Z`; основной формат, совместимый с первой версией |
| `timestamp` | Тот же момент, Unix timestamp в **миллисекундах**; всегда равен `Date.parse(at)` |
| `localDateTime` | Местные дата и время измерения с секундами/миллисекундами, без суффикса UTC |
| `timeZone` | IANA-пояс устройства, зафиксированный при вводе, например `Europe/Moscow` |
| `utcOffsetMinutes` | Смещение местного времени относительно UTC для данного момента; Москва = `180`, Нью-Йорк зимой = `-300` |
| `createdAt` | UTC-время создания записи, отдельно от момента измерения; для старых записей неизвестно (`null` после редактирования) |
| `updatedAt` | UTC-время последнего сохранения записи |

Пример соответствия: `2026-09-27T01:30:45.123` в Москве соответствует
`at = 2026-09-26T22:30:45.123Z`. Числовой timestamp описывает тот же
момент, независимо от пояса просмотра. Локальное время и offset проходят
проверку соответствия `at`; противоречивые данные не принимаются.

Пока все времена происходят от часов устройства: сервера, который мог бы
записать независимый `receivedAt`, ещё нет.

## Ввод и редактирование

Форма фиксирует пояс устройства и начальный момент при открытии. Поле
`datetime-local` показывает местное время; при неизменённом поле сохраняются
исходные секунды и миллисекунды, хотя интерфейс редактирует минуты.
При ручной смене времени оно переводится в UTC в этом поясе.

При редактировании только показателей/комментария сохраняются исходные
`at`, timestamp и локальные метаданные. Это важно при поездках и повторном
часе DST. При изменении времени метаданные пересчитываются в поясе формы;
`createdAt` остаётся прежним. Для записи, сделанной в другом поясе,
форма дополнительно показывает исходное местное время и пояс.

Первоначальный вес использует ту же модель. Демо-данные также содержат
метаданные времени, но остаются явно вымышленными.

## Отображение, графики и сортировка

- Списки, подписи, «Сегодня» и периоды используют **текущий пояс устройства**.
  Пояс из профиля больше не меняет время измерений; он относится к расписаниям.
- Периоды 7/30/90/365 дней ограничиваются местными календарными днями.
  Группировка по дням/неделям и координаты графика также местные.
- Список сортируется по местной дате и времени убывающе. Для одинакового
  местного времени (включая повторный час DST) используется UTC как дополнительный
  ключ. При переводе часов назад этот порядок намеренно может отличаться
  от абсолютной хронологии.
- Карточка «Последняя запись» означает действительно последний момент
  измерения: выбор по абсолютному времени, отображение по местному.
- `localTimeCoordinate` — только условная числовая координата местной шкалы
  графика. Она **не является** timestamp измерения и не сохраняется как таковой.
- Расписание строится в отдельно указанном поясе профиля; ближайшее событие
  показывается пользователю в текущем местном времени устройства.

## Старые записи и проверки

Ключ хранилища `healthnote.diary.v1` и версия структуры 1 сохранены:
добавлены необязательные поля. При чтении старого `at` числовой timestamp
вычисляется в памяти. Неизвестные исходные местное время и пояс не
подменяются текущими. Чтение не переписывает хранилище; новые поля попадут
в него при следующем явном сохранении и в JSON-экспорт.

Прошли 17 тестов и production build. Новые проверки: точность миллисекунд,
смещения +03:00/+05:30, переход через полночь, отдельное время создания,
редактирование после поездки, оба момента повторного часа DST, дополнительный
UTC-ключ сортировки, местная агрегация, совместимость старых записей,
сохранение метаданных и отклонение противоречивого timestamp/offset.
